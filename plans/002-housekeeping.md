## Why this matters

The repo will be public for a hackathon submission. It currently ships with a
malformed npm package name (leading dash), two dead template asset files, an unused
export, a parser parameter that is silently discarded, and a seed-data parser that
throws away its own error report — so a typo in the hand-authored demo sprites
corrupts the first thing judges see, silently. All are small, safe cleanups.

## Current state

  `@pixel-art-tutor` was stripped, leaving a leading dash).
- `src/assets/hero.png` (13KB) and `src/assets/vite.svg` (8.7KB) — zero references

## Steps

### Step 1: Fix the package name

In `package.json` change line 2 to `"name": "pixel-art-tutor",`. Then run
`npm install` to refresh `package-lock.json`.

**Verify**: `grep '"name"' package.json` → `"name": "pixel-art-tutor",` and
`grep -A1 '"pixel-art-tutor"' package-lock.json | head -2` shows the lockfile root
entry updated. `npx tsc -b --pretty false` → exit 0.

### Step 2: Delete dead assets

```bash
git rm src/assets/hero.png src/assets/vite.svg
```

If `src/assets/` is now empty, remove the directory.

**Verify**: `grep -rn "assets/" src/ index.html` → no matches. `npm run build` →
exit 0.

### Step 3: Clean up `rowsToPixels` and `darkestIndex` in `src/engine/pixels.ts`

First confirm no other caller: `grep -rn "rowsToPixels\|darkestIndex" src/ --include="*.ts" --include="*.tsx"`.
Expected callers: `seed.ts` only (twice) for `rowsToPixels`; nothing for
`darkestIndex`. If you find any other caller, STOP.

- Change the signature to `rowsToPixels(rows: string[])` and delete the `palette`
  parameter, the `void palette;` line, and the now-unused `palette` import if it
  becomes unused (check the top of the file — `pixels.ts` imports `luminance,
  normalizeHex` from `./color` for `darkestIndex`; if `darkestIndex` removal makes
  those imports unused, remove them too).
- Delete the entire `darkestIndex` function.

**Verify**: `grep -n "darkestIndex\|void palette" src/engine/pixels.ts` → no
matches. `npx tsc -b --pretty false` → exit 0.

### Step 4: Make seed parsing loud on bad rows

In `src/engine/seed.ts`:
- Change `spriteFromRows` to take the rows and, after calling `rowsToPixels(rows)`,
  throw when `errors.length > 0`:
  ```ts
  const { pixels, width, height, errors } = rowsToPixels(rows);
  if (errors.length > 0) {
    throw new Error(`seed sprite '${name}' has malformed rows: ${errors.join("; ")}`);
  }
  ```
- Restructure `createStarterProject` to remove the two-step frame overwrite. Give
  `spriteFromRows` an optional second-rows parameter, or simpler: keep
  `spriteFromRows` as-is and build the slime explicitly:
  ```ts
  const f0 = rowsToPixels(SLIME_FRAME_1);
  const f1 = rowsToPixels(SLIME_FRAME_2);
  // throw on f0.errors / f1.errors the same way
  ```
  constructing the slime sprite's `frames` array directly from `f0.pixels` /
  `f1.pixels`. Keep the resulting data identical: same ids (`sprite-slime`,
  `sprite-slime-f0`, `sprite-slime-f1`), same name/kind/size, two frames.
  Grass/Dirt keep using `spriteFromRows` (single frame, ids `tile-grass`/`tile-dirt`
  with `-f0` frame ids).

**Verify**: `npx tsc -b --pretty false` → exit 0; `npm run build` → exit 0.

### Step 5: Full gate sweep

```bash
npm run lint && npx tsc -b --pretty false && npm run build
```

**Verify**: all exit 0.
